## Что в индексе

Запросы выполнялись через `cypher-shell` в контейнере `1c-mcp-neo4j` на alcor.

- **148 020 узлов без `project_name`** — старый полный индекс
  (Routine 42 436, Attribute 16 473, Module 3 461, Form 1 615, …).
  Загружен до появления тегирования проектом; какая конфигурация — не подписано.
- **9 814 узлов с `project_name = "LISmcp"`** — MetadataObject 6 077,
  Routine 3 431, Module 306. Формы/реквизиты/ресурсы отсутствуют —
  индекс частичный по составу узлов.

## Ключевая находка: смешение основной конфигурации и расширения

Внутри проекта `LISmcp` объекты лежат **в двух экземплярах** — по одному на
конфигурацию-источник (свойство `config_name`):

```
MATCH (n:MetadataObject) WHERE n.project_name = "LISmcp" AND n.name = "ЗаказУслугУПК"
RETURN n.name, n.config_name;
-- "ЗаказУслугУПК", "Евротест"
-- "ЗаказУслугУПК", "КлиническаяЛаборатория"
```

- «КлиническаяЛаборатория» — основная конфигурация (проект ЛИС1С).
- «Евротест» — расширение (проект ЕвротестРасширение; у узлов расширения есть
  свойство `ОбъектРасширяемойКонфигурации` и урезанный набор свойств).

Загрузчик складывает основную конфигурацию и расширение в один проект
**без оверлея**: adopted-объект расширения НЕ сливается с объектом основной
конфигурации, а ложится рядом дублем. Итог — дублированные реквизиты в досье
(`get_object_dossier` вернул `ЗаказУслуг ×2`, `Штрихкод ×2`) и смешанные
ответы. Это устройство индекса, а не сбой одного запроса.

Запросы без `project_name` (а Codex вызывал именно так) черпают прежде всего
из старого NULL-индекса.

## Источники и процедура переиндексации

- Стек MCP на alcor (`docker ps`): `1c-mcp-graph`, `1c-mcp-neo4j`,
  `1c-mcp-metadata`, `1c-mcp-syntax`, `1c-mcp-docs`, `1c-mcp-templates`,
  `1c-mcp-ssl`, `1c-mcp-forms`, `1c-mcp-codechecker` — up 3+ недель.
- Монтирования graph-сервера: `~/mcp/LISreport -> /app/metadata`,
  `~/mcp/LISfiles -> /app/metadata_files`, `~/mcp/extensions -> /app/extensions`.
- Санкционированная переиндексация: `~/mcp/mcp-deployment/scripts/reindex.sh
  --servers graph` (на alcor; `RESET_DATABASE=true`, 1–4 часа, graph
  недоступен). **RESET сотрёт и NULL-индекс** — если его отчётов нет в
  источниках, проекты Евротест* потеряют graph до своей переиндексации.
- Не проверено (сделать перед reindex): свежесть и состав `~/mcp/LISreport` и
  `~/mcp/extensions`; кто из проектов реально зависит от NULL-индекса.

## Тактическая защита (без переиндексации)

- Все graph-инструменты принимают `project_name` (см.
  `mcp-1c-tools/docs/1c-graph-metadata-mcp.md`). Для ЛИС1С запросы выполнять
  с `project_name="LISmcp"`; дубли «КлиническаяЛаборатория»/«Евротест» читать
  как «основная + расширение», при расхождении структуру брать из
  `1c-code-metadata-mcp` (он отвечал корректно по локальным исходникам).
- Fallback-цепочка из правил (graph → code-metadata → grep=true) сработала
  штатно — дефект именно в данных индекса, не в процедуре.
